# 模型配置：从连接到研究用途

PaperDesk 把“连接服务商”“添加模型实例”“分配研究任务”分开。此组织方式参考 [MaiBot 官方模型配置指南](https://docs.mai-mai.org/manual/configuration/model-config)，任务根据文献阅读、检索与笔记用途设计。

## 先决定需要什么

| 用途 | 选择类型 | 什么时候调用 | 留空时 |
| --- | --- | --- | --- |
| 文献问答 | 擅长推理、长文本与中英文阅读的对话模型 | 在知识库点击“提问”，综合已检索到的原文和笔记并引用来源 | 本地全文检索仍可用 |
| 检索词扩展 | 较快的对话模型，可与问答共用 | 问答前生成中英文术语，提高跨语言匹配；每次问答多一次调用 | 直接使用原始问题检索 |
| 语义检索 | 支持所需语言的 embedding 嵌入模型 | 更新知识库时向量化分块，问答时向量化问题 | 使用关键词检索 |

可以只配置一个问答模型，也可以多个服务商分别配置。添加模型实例不会自动启用；要在第三步分配用途。嵌入模型不是对话模型，不能直接回答问题。

当前支持兼容 OpenAI 的 chat/completions 与 embeddings 接口，使用 Bearer API Key，或无需鉴权的本地服务。仅提供 Responses、原生 Claude/Gemini 等其它协议的端点需要兼容网关，不能直接填聊天网页地址。具体模型 ID 与可用性请以你所用服务商的接口文档为准。

## 三步设置

1. 添加服务商：显示名自定；Base URL 是 API 根地址，通常以 /v1 结尾；API Key 从服务商开发者控制台创建。无需鉴权的本地兼容服务可留空。
2. 添加模型实例：选择所属服务商，填精确模型 ID，给它起易懂的名字，选择对话或嵌入类型。点击“测试模型”发送简短请求，可能产生少量 API 费用。
3. 分配研究任务并保存。语义检索分配嵌入模型后，去知识库点击“更新知识库”。

服务商密钥已保存时，输入框留空会保留原值；勾选“清除已有密钥”才删除。配置只存在本机，不会通过文献同步。不会读取 Hermes 的模型密钥。

## 选择建议

先选择你已有、可稳定调用的兼容服务，测试一个问答模型。问答效果取决于原文是否有文字层、检索是否找到相关段落和模型理解能力。需要跨语言查找时，可增加多语言嵌入模型；检索词扩展可先与问答共用，以减少配置负担。

当前没有把 OCR、自动改写笔记或自动批量生成内容绑定成模型任务，避免未明确触发时改动研究资料。文献问答会把检索到的片段发送给对应服务；语义构建会发送文献和笔记分块。所有接口留空时，整理、阅读、写笔记、去重和全文搜索均可离线使用。

## 常见问题

- 401/403：检查 API Key、余额或该模型权限。
- 404/非 JSON：检查是否把网页地址或完整 chat/completions 路径填成了错误 Base URL。
- 向量格式不对：确认模型支持 embeddings，且类型选择“嵌入模型”。
- 扩展失败：系统保留原问题继续检索，并显示提示。
- 检索不到：先用原文关键词，确认 PDF 已提取文字；修改模型后重新更新知识库。
